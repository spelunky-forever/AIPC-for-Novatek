# Inference Reference (Linux x86 Host & ARM Linux Target)

`scripts/onnxwrapper.py` (for ARM Linux HTP) and `scripts/onnxwrapper_x86.py` (for x86 host simulation) are drop-in `onnxruntime` replacements invoked via `python scripts/qai <infer_script>.py`.

---

## 1. Critical Runtime Isolation Rules

1. **Separate Processes for Baseline vs. QNN (Mandatory)**:
   - Never import `torch` or run `onnxruntime` CPU baseline in the same Python process as `python scripts/qai`.
   - `qai` hot-swaps `sys.modules["onnxruntime"]`, and PyTorch's C++ allocator collides with QNN's heap allocator causing silent segfaults.
   - **Standard Pattern**: Process A runs PyTorch / ORT CPU (`CPUExecutionProvider`) $\rightarrow$ saves `.npy`; Process B runs `python scripts/qai` $\rightarrow$ saves `.npy`; Process C computes Cosine similarity.
2. **Always Use `qai` Launcher — Never Call `QNNContext` Directly**:
   - QAIRT reorders output tensors at compile time. `onnxwrapper` reads `<model>.yaml` (generated by `qai_inspect_onnxio.py`) to restore the original ONNX output order. Direct `QNNContext.Inference()` returns HTP internal order and silently mismatches outputs.
3. **Match Source I/O Contract**:
   - Inference scripts must output user-facing task results (images, labels, bounding boxes, transcripts, generated text)—use `.npy` only for accuracy debugging.

---

## 2. Mode A: Local Linux x86 Host Verification

Use `onnxwrapper_x86.py` for host-side functional verification when no HTP hardware is attached:
- `onnxwrapper_x86.py` is **CPU-only simulation** (ignores `QAI_QNN_RUNTIME=HTP`).
- **NEVER** deploy `onnxwrapper_x86.py` to the ARM Linux target board.
- Requires `QAIRT_SDK_ROOT` to be set (probes `$QAIRT_SDK_ROOT/bin/x86_64-linux-clang`).

```bash
# On Linux x86 host (ensure onnxwrapper_x86.py is active or selected by qai)
python scripts/qai infer_model.py
```

---

## 3. Mode B: ARM Linux Target Board HTP Inference

### Step 1: Wrapper & Artifact Preflight
1. Confirm `onnxwrapper.py` contains `import qai_appbuilder` (not the x86 simulation stub).
2. Quarantine stale `*.bin` files in the working directory so the wrapper does not pick up an old binary:
   ```bash
   mkdir -p _ctx_backup && mv -f *.bin _ctx_backup/ 2>/dev/null || true
   ```
3. Place the context binary and `.yaml` alongside `<model>.onnx`:
   - **Linux Resolution Priority**: `model.htp.bin` $\rightarrow$ `model.so.bin` $\rightarrow$ `model.so` $\rightarrow$ `libmodel.htp.bin` $\rightarrow$ `libmodel.so.bin` $\rightarrow$ `libmodel.so` $\rightarrow$ `model.bin` $\rightarrow$ `libmodel.bin` (or `<model>.onnx.so.bin`).
   - **Mandatory `.yaml`**: Copy `<model>.yaml` alongside `<model>.onnx`; without it, output tensor order and dot-formatted names (`past_key_values.0.key`) cannot be restored.

### Step 2: Pin QNN Runtime Libraries (Mandatory on ARM Linux)
`onnxwrapper.py` does **not** read `QAIRT_SDK_ROOT`—it defaults to bundled `qai_appbuilder/libs/` unless `QAI_QNN_LIBS_DIR` is explicitly set, which causes ABI segfaults or `Failed to load skel (4000)` / `Transport layer setup failed (14001)`:
```bash
export QAI_QNN_LIBS_DIR="$QAIRT_SDK_ROOT/lib/aarch64-oe-linux-gcc11.2"
export LD_LIBRARY_PATH="$QAI_QNN_LIBS_DIR:$LD_LIBRARY_PATH"
export ADSP_LIBRARY_PATH="$QAIRT_SDK_ROOT/lib/hexagon-v${DSP_ARCH}/unsigned"
export QAI_QNN_RUNTIME=HTP

# If FastRPC daemon expects .so.2 SONAME:
# ln -sf libQnnHtpV73Skel.so "$ADSP_LIBRARY_PATH/libQnnHtpV73Skel.so.2"

python3 scripts/qai infer_model.py
```

## 4. Common Inference Pitfalls

- **Input Layout (`NCHW` vs `NHWC`)**:
  - Models converted with `--preserve_io` (default in `qai_convert_fp.py`/`qai_convert_int.py`) keep **NCHW** `[1, C, H, W]`.
  - Models converted without `--preserve_io` expect **NHWC** `[1, H, W, C]`. Passing the wrong layout causes silent garbage predictions.
- **Multiple Models in One Process (`QNNContext` Global State)**:
  - `qai_appbuilder.QNNContext` shares global backend state—opening two `InferenceSession` instances simultaneously overwrites the first model's handle.
  - **Rule**: Load $\rightarrow$ run $\rightarrow$ `del sess` sequentially (e.g., `del enc_sess` before creating `dec_sess`), or assign globally unique `model_name` strings if using `QNNContext` directly.
- **HTP BURST Mode Lifecycle** (when using `qai_appbuilder` directly):
  - Call `PerfProfile.SetPerfProfileGlobal(PerfProfile.BURST)` **after** loading at least one `QNNContext` (calling it earlier silently fails with `0x32c9`), hold it once across the entire inference loop, and call `PerfProfile.RelPerfProfileGlobal()` **before** `del model`.
- **HF `transformers` v4/v5 Compatibility**:
  - Avoid `Processor.from_pretrained(local_dir)` on target boards where `transformers` versions differ. Instantiate `WhisperFeatureExtractor.from_pretrained()` and `WhisperTokenizer.from_pretrained()` separately and combine them.

## 5. `qnn-net-run` Diagnostic Fallback

If `python3 scripts/qai` segfaults (exit 139) due to a `qai_appbuilder` vs. QAIRT SDK version mismatch, rebuild `qai_appbuilder` from source against `$QAIRT_SDK_ROOT`. For quick CLI diagnostics only:
```bash
# input_list.txt format: input_name:=/abs/path/input.raw
$QAIRT_SDK_ROOT/bin/aarch64-oe-linux-gcc11.2/qnn-net-run \
  --backend "$QAI_QNN_LIBS_DIR/libQnnHtp.so" \
  --retrieve_context model.onnx.so.bin \
  --input_list input_list.txt \
  --output_dir ./netrun_out \
  --use_native_input_files --use_native_output_files
# Outputs are written to ./netrun_out/Result_0/<output_name>.raw (FP16 if nbytes == nelems * 2)
```
